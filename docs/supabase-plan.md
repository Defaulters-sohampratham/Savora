# Savora Supabase Plan

This MVP keeps demo data local. When Savora is ready for persistence, Supabase should store the worker profile, monthly income records, and calculation snapshots separately so the deterministic engine can be re-run safely.

## Tables

### profiles

Stores the worker-facing profile.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid primary key` | Generated by Supabase |
| `user_id` | `uuid null` | Links to auth later |
| `display_name` | `text not null` | Worker name |
| `role` | `text not null` | Delivery partner, driver, home services, etc. |
| `city` | `text not null` | Used for context only |
| `essential_expenses` | `integer not null` | Monthly essentials in paise-free INR units for MVP |
| `monthly_emi` | `integer not null default 0` | Added into essential total |
| `current_savings` | `integer not null default 0` | Current emergency savings |
| `created_at` | `timestamptz not null default now()` | Audit timestamp |
| `updated_at` | `timestamptz not null default now()` | Audit timestamp |

### income_records

Stores each monthly income entry.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid primary key` | Generated by Supabase |
| `profile_id` | `uuid not null references profiles(id)` | Owner profile |
| `amount` | `integer not null` | Monthly income in INR units for MVP |
| `income_date` | `date not null` | Month-end date or normalized monthly date |
| `source_label` | `text null` | Future support for app/platform source |
| `created_at` | `timestamptz not null default now()` | Audit timestamp |

### financial_snapshots

Stores the result shown to the worker at a point in time.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid primary key` | Generated by Supabase |
| `profile_id` | `uuid not null references profiles(id)` | Owner profile |
| `state` | `text not null` | Critical, Low, Normal, High, Buffer Complete |
| `latest_income` | `integer not null` | From engine output |
| `average_income` | `integer not null` | From engine output |
| `essential_total` | `integer not null` | Expenses plus EMI |
| `surplus` | `integer not null` | Latest income minus essentials |
| `recommended_saving` | `integer not null` | From deterministic engine |
| `remaining_cash` | `integer not null` | Surplus minus saving |
| `buffer_target` | `integer not null` | Three months of essentials |
| `runway_months` | `numeric not null` | Savings divided by essential total |
| `forecast` | `jsonb not null` | Conservative, expected, optimistic |
| `shortfall` | `jsonb not null` | Exists and amount |
| `confidence` | `text not null` | Low, Medium, High |
| `factors` | `jsonb not null` | Number-grounded explanation factors |
| `scenario` | `jsonb null` | 20% drop result |
| `created_at` | `timestamptz not null default now()` | Snapshot timestamp |

## RLS Direction

Enable row-level security before real users are added. Once auth exists, every table should restrict rows to `auth.uid() = profiles.user_id`. Demo profiles can stay local or be stored under a seeded demo account.

## Integration Notes

- Keep the existing TypeScript finance engine as the only calculator.
- Fetch profiles and income records on the server side in Next.js.
- Use Server Actions for user edits later.
- Store snapshots only after calculation succeeds, never before.
- Do not ask the LLM to calculate or alter any stored numeric value.
